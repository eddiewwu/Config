# Config Repo — Claude Guidelines

This repo is Ed's personal config backup. Primary editor is VS Code + Claude Code CLI. NeoVim config is kept but deprioritized.

## Repo Structure

| Folder | Purpose |
|---|---|
| `skills/` | Agent Skills in the standard `SKILL.md` format — shared by all agents, not Claude-specific |
| `.github/` | GitHub Copilot repo instructions (`copilot-instructions.md`) |
| `tmux/` | tmux config — `tmux.conf` (live copy at `~/.tmux.conf`) |
| `nvim/` | NeoVim config — archived, low priority |
| `herdr/` | Herdr terminal workspace config (live copy at `%APPDATA%\herdr\config.toml`) |
| `agents/` | Model-agnostic global agent instructions (canonical live copy at `~/.config/AGENTS.md`) |
| `claude/` | Claude Code global CLAUDE.md (live copy at `~/.claude/CLAUDE.md`, imports `~/.config/AGENTS.md`) |

## Available Skills (all agents)

Skills live in `skills/<name>/SKILL.md` in the standard Agent Skills format (YAML frontmatter with `name` and `description`), so the same folders load in Claude Code, GitHub Copilot, Codex, and opencode. Install by copying the folders into the agent's skills directory (`~/.claude/skills/`, `~/.copilot/skills/`, etc.).

- `doc` — Generate a README.md for the current project
- `mr-review` — Code review and bug detection on PRs or code changes
- `summary` — Summarize file contents or conversation context
- `pr-workflow` — Plan first, then auto-open a PR; merging is always the owner's manual step
- `pr-workflow` — Phased repo workflow: plan first, then automatically open a PR; merging is always the owner's manual step

## General Coding Rules

- Never commit secrets (API keys, tokens, credentials) — use environment variables
- Run lint/typecheck before committing
- Write clear commit messages
- Never force push to main
- Prefer explicit over implicit
- Fail fast, fail loud

## Config Sync Rule

Whenever Ed updates any config on the machine (tmux `~/.tmux.conf`, nvim `~/.config/nvim`, Claude skills, agent instructions, etc.), mirror the change into the matching folder in this repo and commit. This repo is the backup of record. If a config has no folder here yet, create one. Always offer to commit/push after mirroring.

### AGENTS.md fan-out rule

The canonical global agent instructions live at `~/.config/AGENTS.md`. Symlinks are not available (no admin/Developer Mode), so these are plain copies that must be re-synced whenever the canonical file changes:

- `~/.codex/AGENTS.md` (Codex/GPT)
- `~/.config/opencode/AGENTS.md` (opencode)
- `agents/AGENTS.md` (this repo)

Claude Code needs no copy: `~/.claude/CLAUDE.md` imports the canonical file via `@~/.config/AGENTS.md`.

GitHub Copilot needs no copy either: it reads `agents/AGENTS.md` and `.github/copilot-instructions.md` in this repo, and personal skills from `~/.copilot/skills/`.

## Memory Files

Personal memory about Ed — the CLAUDE.md / MEMORY.md system and related notes — is maintained separately, outside this repo. Never copy memory files here. This repo holds skills and configs only.
