# Config Repo — Claude Guidelines

This repo is Ed's personal config backup. Primary editor is VS Code + Claude Code CLI. NeoVim config is kept but deprioritized.

## Repo Structure

| Folder | Purpose |
|---|---|
| `obsidian/` | Obsidian vault system backup — CLAUDE.md, MEMORY.md, voice principles, budget |
| `skills/` | Claude Code CLI custom skills |
| `tmux/` | tmux config — `tmux.conf` (live copy at `~/.tmux.conf`) |
| `nvim/` | NeoVim config — archived, low priority |

## Available Skills (Claude Code CLI)

- `/doc` — Generate a README.md for the current project
- `/mr-review` — Code review and bug detection on PRs or code changes
- `/summary` — Summarize file contents or conversation context

## General Coding Rules

- Never commit secrets (API keys, tokens, credentials) — use environment variables
- Run lint/typecheck before committing
- Write clear commit messages
- Never force push to main
- Prefer explicit over implicit
- Fail fast, fail loud

## Config Sync Rule

Whenever Ed updates any config on the machine (tmux `~/.tmux.conf`, nvim `~/.config/nvim`, Claude skills, Obsidian system files, etc.), mirror the change into the matching folder in this repo and commit. This repo is the backup of record. If a config has no folder here yet, create one. Always offer to commit/push after mirroring.

## Obsidian Backup

Files in `obsidian/` are manual copies of the live vault at `D:\Obsidian`. When you update the vault's system files, copy them here and commit to keep GitHub in sync.
